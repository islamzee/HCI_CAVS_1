CAVS-1 dashboard · field guide

Running the dashboard on the MTX

The MTX computer has no internet, so everything travels on a USB drive. On the MTX, the dashboard replays a bag that is already stored there. The code stays the same; one settings file, pod.env, tells it which bag to play.

The journey

Your laptop

  • Has internet
  • Downloads the image
  • Saves it to a file

USB drive

  • cavs-image-amd64.tar or -arm64
  • Implementation folder

MTX computer

  • No internet
  • Already has the bag
  • Runs the pod

Browser

  • On the MTX, or a device on its network
  • Port 8765

Each step below carries the colour of the place where you do it.

What runs on the MTX

Steps

1

Check the MTX before you go

MTX

Ask whoever has access to run these two commands on the MTX:

podman --version   # needs 4 or newer
uname -m           # x86_64 = Intel/AMD, aarch64 = ARM
Write down the uname -m answer. Step 2 depends on it.
2

Save the image to a file

Laptop · internet
podman pull --platform linux/amd64 ghcr.io/islamzee/hci_cavs_1/cavs-bag-bridge:latest
podman save -o cavs-image-amd64.tar ghcr.io/islamzee/hci_cavs_1/cavs-bag-bridge:latest
  • MTX said x86_64: keep linux/amd64.
  • MTX said aarch64: use linux/arm64.
Don't skip --platform. A Mac is ARM and would otherwise save the wrong one.
3

Copy two things to the USB drive

USB drive
  • cavs-image-amd64.tar (Intel/AMD) or cavs-image-arm64.tar (ARM), about 1 GB each. Ready-made copies of both are in MTX_transfer/ at the top of the repo on Zeenat's laptop (made 20 Nov 2026, not in git).
  • The repo's Implementation folder. Run git pull first. You don't need Dataset: the bag is already on the MTX.
4

Load and set up (once)

MTX
cp -r /media/<usb>/Implementation ~/cavs
podman load -i /media/<usb>/cavs-image-amd64.tar   # or cavs-image-arm64.tar on an ARM MTX
cd ~/cavs
cp pod.env.example pod.env
nano pod.env

In pod.env, set the bag folder. Save with Ctrl+O, Enter, then exit with Ctrl+X.

BAG_DIR=/full/path/to/their/bag
IMAGE=ghcr.io/islamzee/hci_cavs_1/cavs-bag-bridge:latest
  • BAG_DIR is the folder that holds metadata.yaml and the .mcap file.
  • Full path, no spaces around =, no quotes.
  • Don't know where the bag is? find / -name metadata.yaml 2>/dev/null
5

Start it

MTX
./pod.sh up
./pod.sh topics      # after about 10 seconds
Good: it prints Bag: /full/path/to/their/bag, and topics lists /mtx/odom with a rate.
It says autonomy_demo_slim? Then pod.env wasn't read. Check the file name and that it's next to pod.sh.
6

Open the dashboard

Browser
  • On the MTX itself: http://localhost:8765/dashboard/
  • From a laptop or tablet on the MTX network: run hostname -I on the MTX, then open http://<that address>:8765/dashboard/
Localhost works but the other device doesn't? The MTX firewall blocks port 8765. Ask whoever manages the MTX.
7

Stop it when you're done

MTX
./pod.sh down

Always stop it. It keeps reading the bag, and the MTX is the vehicle's computer.

If something goes wrong

What you seeWhat to do
Dashboard waits for data./pod.sh logs player and ./pod.sh logs bridge show why
./pod.sh logs bridge says "exec format error"Wrong processor type. Redo step 2 with the other --platform
Pod already exists./pod.sh down, then ./pod.sh up
Some panels empty, others fineThat bag doesn't have those topics. Nothing to fix in the setup

Other commands

BAG_DIR=/other/bag ./pod.sh up   # another bag, this run only
RATE=0.5 ./pod.sh up             # slower playback
./pod.sh restart                 # stop and start again
./pod.sh status                  # is it running?
